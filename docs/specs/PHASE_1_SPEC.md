# Phase 1 Technical Specification: Core Infrastructure

## 1. Objective
Stand up the complete, zero-cost infrastructure backbone (PostgreSQL 18, Keycloak, Kong OSS DB-less, and Nginx Edge LB) using Docker Compose profiles and strict memory caps, before decomposing any Python application code.

---

## 2. Network Topology & Port Map

Three isolated bridge networks enforce least-privilege traffic flow:
- **`edge-net`**: Nginx <-> Kong, Nginx <-> Keycloak (auth UI), Nginx <-> Frontend (Phase 3).
- **`app-net`**: Kong <-> Backend Microservices, Backend Microservices <-> Keycloak (internal JWKS fetch).
- **`data-net`**: PostgreSQL 18 <-> Keycloak, PostgreSQL 18 <-> Backend Microservices (no direct exposure to Nginx or Kong).

| Service | Container Name | Networks | Internal Port | Host Port (Local) | Profiles | Mem Limit |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **PostgreSQL 18** | `zd-postgres` | `data-net` | `5432` | `5432` | `core`, `auth`, `full` | `256m` |
| **Keycloak** | `zd-keycloak` | `edge-net`, `app-net`, `data-net` | `8080` | `8080` | `auth`, `full` | `512m` |
| **Kong OSS** | `zd-kong` | `edge-net`, `app-net` | `8000` (proxy), `8001` (admin) | `8000` (proxy only) | `auth`, `full` | `256m` |
| **Nginx LB** | `zd-nginx` | `edge-net` | `80`, `443` | `80`, `443` | `core`, `auth`, `full` | `64m` |

## 3. Environment Variable Schema (`.env.example`)
All secrets and credentials are externalised into `.env` (git-ignored), with safe dev defaults documented in `.env.example`:
- **PostgreSQL:** `POSTGRES_USER`, `POSTGRES_PASSWORD`, `CAMPAIGN_DB_USER`, `CAMPAIGN_DB_PASSWORD`, `TRACKING_DB_USER`, `TRACKING_DB_PASSWORD`, `KEYCLOAK_DB_USER`, `KEYCLOAK_DB_PASSWORD`
- **Keycloak:** `KEYCLOAK_ADMIN`, `KEYCLOAK_ADMIN_PASSWORD`, `KC_HOSTNAME=localhost`
- **Kong:** `KONG_LOG_LEVEL=warn`
- **App Common:** `JWKS_URL=http://zd-keycloak:8080/realms/zero-dose-realm/protocol/openid-connect/certs`

## 4. Component Contracts

### 4.1 PostgreSQL 18 (`infra/postgres/init-databases.sql`)
Mounted into `/docker-entrypoint-initdb.d/` so it executes automatically on first volume boot:
- Creates three isolated databases: `campaign_db`, `tracking_db`, `keycloak_db`.
- Creates three least-privilege service roles (`campaign_user`, `tracking_user`, `keycloak_user`), each granted ownership/privileges **only** on its respective database.
- Runtime tuning in `docker-compose.yml`: `shared_buffers=128MB`, `max_connections=100`.
- Healthcheck: `pg_isready -U ${POSTGRES_USER}`.

### 4.2 Keycloak (`infra/keycloak/realm-export.json`)
Imported automatically at startup via `start-dev --import-realm` backed by `keycloak_db`:
- **Realm:** `zero-dose-realm`
- **Token Lifespans:** Access token = **300 seconds (5 min)**; Refresh token = 30 min.
- **Realm Roles:** `admin`, `field_worker`
- **Clients:**
  1. `zd-frontend` (Public client, Standard Flow / PKCE enabled, Redirect URIs: `https://localhost/*`, `http://localhost:5173/*`).
  2. `zd-cli-test` (Public client, Direct Access Grants enabled — **dev/CI testing only** so `curl` and GitHub Actions can mint JWTs cleanly without a browser).
- **Seeded Dev Users:**
  - `admin.user` / `AdminPass123!` -> role: `admin`
  - `worker.user` / `WorkerPass123!` -> role: `field_worker`
- **JVM Cap:** `JAVA_OPTS_APPEND="-Xms256m -Xmx512m"`.
- **Healthcheck:** HTTP check on port `9000` (`/health/ready`).

### 4.3 Kong OSS DB-less (`infra/kong/kong.yml`)
- **Mode:** `KONG_DATABASE=off`, `KONG_DECLARATIVE_CONFIG=/etc/kong/kong.yml`.
- **Memory Tuning:** `KONG_NGINX_WORKER_PROCESSES=1`, `KONG_MEM_CACHE_SIZE=64m`.
- **Declared Services & Routes:**
  - `/api/v1/campaigns` -> `http://campaign-service:8001` (`strip_path: false`)
  - `/api/v1/beneficiaries` & `/api/v1/vaccinations` -> `http://tracking-service:8002` (`strip_path: false`)
  - `/api/v1/analytics` & `/api/v1/metrics` -> `http://analytics-service:8003` (`strip_path: false`)
  - `/health` -> Dummy/echo or Kong status route for Phase 1 smoke verification before services exist.
- **Global Plugins:**
  - `cors`: allows `https://localhost`, `http://localhost:5173`, headers `Authorization, Content-Type`.
  - `rate-limiting`: `100` requests/minute (`policy: local`) per client IP.

### 4.4 Nginx Edge Load Balancer (`infra/nginx/nginx.conf`)
- Listens on `80` (redirects to `443`) and `443 ssl` (self-signed cert generated by `infra/nginx/generate-certs.sh` for `localhost`).
- **Routing Rules:**
  - `/api/` -> proxies to `http://zd-kong:8000` (passes `X-Forwarded-For`, `X-Forwarded-Proto`).
  - `/auth/` -> proxies to `http://zd-keycloak:8080` (with proper `X-Forwarded-Host` and buffer sizing for OIDC headers).
  - `/healthz` -> returns `200 OK` directly from Nginx.
  - `/` -> returns a Phase 1 placeholder `200 OK` (replaced by React SPA container in Phase 3).

## 5. Phase 1 Validation Gate (Must Pass Before Phase 2)
1. **Stack Boot:** `make up-auth` brings up `zd-postgres`, `zd-keycloak`, `zd-kong`, and `zd-nginx` all in `healthy` state with total RAM < 1.35 GB (`docker stats --no-stream`).
2. **DB Isolation:** `psql` confirms `campaign_db`, `tracking_db`, and `keycloak_db` exist and `campaign_user` cannot connect to `tracking_db`.
3. **JWT Minting & JWKS:**
   - `curl` against Keycloak token endpoint with `admin.user` returns a valid JWT containing `"roles": ["admin"]`.
   - `curl` against Keycloak `/certs` endpoint returns the public JWKS JSON.
4. **Edge -> Gateway Flow:** `curl -k https://localhost/healthz` returns `200 OK`, and hitting `https://localhost/api/v1/campaigns` reaches Kong (returning expected upstream `503` / `502` with Kong rate-limit headers `X-RateLimit-Limit-Minute: 100` until Phase 2 services are added).
